verification-before-completion

Use when about to claim work is complete, fixed, or passing, before committing or creating PRs - requires running verification commands and confirming output before making any success claims; evidence before assertions always

n03 · W 层 · 流程 · main_flow

The Gate Function

流程节点。每个步骤的首行 ⇢ 是进入该步的条件;类型徽章来自语义层的步骤分型,◆ 验证闸口、⏸ 需用户确认;上方弧线是条件跳转(蓝,虚线 = 推断)与重试环(橙);下方外部节点栏里,点线是别的节点供给本步的依赖,橙线是兜底去向;⦿ 是终止点。

BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH evidence
5. ONLY THEN: Make the claim

Skip any step = lying, not verifying

n09 · R 层 · 路由/激活 · scope

When To Apply

路由/激活节点,不是流程步骤。

ALWAYS before:

  • ANY variation of success/completion claims
  • ANY expression of satisfaction
  • ANY positive statement about work state
  • Committing, PR creation, task completion
  • Moving to next task
  • Delegating to agents

Rule applies to:

  • Exact phrases
  • Paraphrases and synonyms
  • Implications of success
  • ANY communication suggesting completion/correctness

触发条件(R 层)

  • 声称完成/修复/通过之前,提交或建 PR 之前必须先跑验证命令并确认输出 Use when about to claim work is complete, fixed, or passing
  • 任何形式的成功/完成声称之前都要应用本规则 ANY variation of success/completion claims
  • 提交、建 PR、任务完成时触发 Committing, PR creation, task completion
  • 把任务委派给 agent 时也要触发 Delegating to agents
