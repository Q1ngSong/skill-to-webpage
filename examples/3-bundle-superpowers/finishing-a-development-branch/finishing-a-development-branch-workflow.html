finishing-a-development-branch

在实现完成、测试全部通过之后接管收尾:先验测试、再探工作区环境,然后给出一份逐字固定的选项菜单(本地合并 / 推送开 PR / 原样保留 / 丢弃),按用户所选执行,并只在该清理时清理 worktree 与分支。何时用:代码写完、测试全绿,需要决定这份工作怎么并回主线时。

执行总纲:收尾一条开发分支只有一条主线:先验测试,再探工作区环境,给出逐字固定的选项菜单,执行用户所选,最后只在该清理时清理 整份 skill 就是一条不可跳步的直线:Verify tests → Detect environment → Present options → Execute choice → Clean up。前两步是闸门——测试不过就地停住,环境判定决定菜单是 4 项还是 3 项;第四步只许原样抛出固定选项、不加解释;第五步分派到四条互斥分支;第六步只为 Option 1 与 4 运行,且必须先做归属检查:只清理自己建在 .worktrees/、worktrees/ 或 ~/.config/superpowers/worktrees/ 下的工作区。

Step 2 · Detect Environment RETRIEVE

目标 出菜单前先判定工作区状态:普通仓库、具名分支 worktree,还是 detached HEAD Determine workspace state before presenting options

怎么做

  1. 取 git-dir 与 git-common-dir 的真实绝对路径做对比 GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)

规则

  • 两者相等 = 普通仓库,给标准 4 项,没有 worktree 需要清理 `GIT_DIR == GIT_COMMON` (normal repo) | Standard 4 options
  • 两者不等且是具名分支 = 标准 4 项,清理按归属判定(见 Step 6) `GIT_DIR != GIT_COMMON`, named branch | Standard 4 options
  • 两者不等且 detached HEAD = 只给 3 项(无本地合并),不清理 `GIT_DIR != GIT_COMMON`, detached HEAD | Reduced 3 options (no merge)

质量标准 0/1

工具

git rev-parse --git-dir / --git-common-dir

输出

  • 环境判定结果:决定菜单形态与清理方式 This determines which menu to show and how cleanup works

Step 11 · Cleanup Workspace TOOL_CALL ◆ 验证闸口

目标 只为 Option 1 与 4 运行:按 worktree 归属决定移除还是留手 Only runs for Options 1 and 4.

怎么做

  1. 取 GIT_DIR、GIT_COMMON 与 worktree 根路径 WORKTREE_PATH=$(git rev-parse --show-toplevel)
  2. cd 回主仓根后 remove 该 worktree,再 prune 自愈残留登记 git worktree remove "$WORKTREE_PATH"

规则

  • 否则工作区归宿主环境(harness)所有,不得移除;平台若提供退出工具就用它 The host environment (harness) owns this workspace. Do NOT remove it.
  • Option 2 与 3 永远保留 worktree Options 2 and 3 always preserve the worktree

判据 0/2

质量标准 0/3

常见翻车

  • 在被删 worktree 内部执行 remove,命令会静默失败 Command fails silently when CWD is inside the worktree being removed
  • 清理 harness 建的 worktree 会造成幽灵状态 Removing a worktree the harness created causes phantom state

治理约束

宿主拥有的工作区:留在原地或交给平台的 workspace-exit 工具 If your platform provides a workspace-exit tool, use it.

工具

git worktree remove
git worktree prune(自愈:清掉过期登记)
原文 · SKILL.md:171-193

n04 · S 层 · 语义/知识 · failure_modes

Common Mistakes

七条「问题—纠正」对,分别钉住执行路径上最容易出错的步骤:跳过测试、开放式提问、错误清理、删除顺序。

Skipping test verification

  • Problem: Merge broken code, create failing PR
  • Fix: Always verify tests before offering options

Open-ended questions

  • Problem: "What should I do next?" is ambiguous
  • Fix: Present exactly 4 structured options (or 3 for detached HEAD)

Cleaning up worktree for Option 2

  • Problem: Remove worktree user needs for PR iteration
  • Fix: Only cleanup for Options 1 and 4

Deleting branch before removing worktree

  • Problem: git branch -d fails because worktree still references the branch
  • Fix: Merge first, remove worktree, then delete branch

Running git worktree remove from inside the worktree

  • Problem: Command fails silently when CWD is inside the worktree being removed
  • Fix: Always cd to main repo root before git worktree remove

Cleaning up harness-owned worktrees

  • Problem: Removing a worktree the harness created causes phantom state
  • Fix: Only clean up worktrees under .worktrees/, worktrees/, or ~/.config/superpowers/worktrees/

No confirmation for discard

  • Problem: Accidentally delete work
  • Fix: Require typed "discard" confirmation

Red Flags

Never 七条与 Always 七条,是压在整条执行路径上的治理约束,尤其管住删除与 worktree 清理。

Never:

  • Proceed with failing tests
  • Merge without verifying tests on result
  • Delete work without confirmation
  • Force-push without explicit request
  • Remove a worktree before confirming merge success
  • Clean up worktrees you didn't create (provenance check)
  • Run git worktree remove from inside the worktree

Always:

  • Verify tests before offering options
  • Detect environment before presenting menu
  • Present exactly 4 options (or 3 for detached HEAD)
  • Get typed confirmation for Option 4
  • Clean up worktree for Options 1 & 4 only
  • cd to main repo root before worktree removal
  • Run git worktree prune after removal

  • 绝不在测试失败的情况下继续往下走 Proceed with failing tests →
